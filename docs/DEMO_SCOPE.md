# 交互 Demo 范围与完成线

## 1. 要验证的问题

当前 Demo 只验证一个产品假设：

> 玩家能否依据不完整情报进行核验、准备和传播，并通过这些选择改变黑风谷局势，同时理解结果为什么发生。

CLI 是这个假设的可玩性实验台，不是最终客户端，也不承担完整修仙玩法。

## 2. 冻结范围

Demo 保留以下行动：

* 等待；
* 核验情报；
* 私下分享情报；
* 购买解瘴丹；
* 地点移动；
* 修炼与疗伤。

完成线之前不新增借贷、招募、队伍、战斗、伏击、逃亡、装备、任务、技能树、自由对话、更多场景或正式 Godot UI。

任何新增机制都必须直接解除核心体验闭环中的已验证阻塞，并替代同等规模的待办；“世界观上应该存在”不构成加入 Demo 的理由。

## 3. 核心体验闭环

1. 玩家获得第 24 天成熟的低可信传闻；
2. 玩家决定是否核验，并看到认知变化；
3. 玩家决定是否购买进入黑风谷所需的解瘴丹；
4. 玩家决定是否把当前相信的说法交给特定 NPC；
5. 玩家等待公开窗口、移动并参与或放弃核心争夺；
6. 终局总结玩家行动、最终状态和可证明的情报影响。

界面只能展示玩家已知内容。真实成熟日期、NPC 私有认知、策略评分和世界内部标记不得作为提示泄露。

## 4. 自动验收路线

| 路线 | 关键选择 | 当前验收证据 |
| --- | --- | --- |
| 旁观者 | 全程等待 | 世界独立推进，并由李玄取得青髓芝 |
| 求真者 | 核验传闻后等待 | F02 变为已核实，终局保留玩家认知与行动摘要 |
| 准备者 | 购买、五次修炼、按窗口入谷 | 玩家能以足够准备值取得青髓芝 |
| 传播者 | 核验后前往青岚门，把真实日期线索告知沈砚秋 | 沈砚秋改变首选行动、提前准备，并取代李玄取得青髓芝 |

这些路线由 `internal/app` 测试直接通过动态行动目录执行，不使用预写引擎命令绕过客户端边界。

## 5. Demo 完成门禁

以下条件全部满足后，才讨论 Godot 接入或扩大玩法：

* 新玩家不读代码也能完整玩到第 30 天；
* 每个行动都明确反馈开始、进度、完成和可见状态变化；
* 玩家不会因路线或时间窗口不透明而无目的等待；
* 至少三种策略产生玩家可辨认的不同终局状态；
* 至少一条传播路线能证明 NPC 行动或最终归属因玩家情报而改变；
* 结局总结能区分“情报已送达”和“情报改变了 NPC 决策”；
* 存档回放结果一致，玩家视图不泄露内部真值；
* 统一质量门禁持续通过。

## 6. 已闭合的情报因果链

传播路线现在形成一条可审计的闭环：

1. 玩家核验 F02，获得 F01 的真实成熟日期线索；
2. 玩家在第 4 天前往青岚门，把 F01 告知沈砚秋；
3. 第 5 天，沈砚秋由自行核验改为提前调集弟子和解瘴物资；
4. 额外支援和准备状态改变争夺评分；
5. 最终归属由旁观路线中的李玄变为沈砚秋；
6. 终局摘要分别记录“情报进入认知”和“情报改变首选行动”。

至此不再存在需要通过扩展通用行动系统解决的机制缺口。下一步是人工试玩验证提示是否足够易懂，并处理试玩中可复现的闭环阻塞。
