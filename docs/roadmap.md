# 凡途项目路线图

- 状态：持续推进
- 更新日期：2026-08-03
- 当前基线：CLI 完整游戏流程、NPC 多轮对话、受约束世界导演、内容编译器和三套内容包均可运行
- 当前重点：将 CLI 已建立的严格 AI 契约贯通 Server 与 Godot，并补齐取消、审计、重放和真实模型门禁

## 1. 路线图目标

下一阶段不再以增加零散 AI 功能为目标，而是建立所有客户端一致、可取消、可审计、可重放的 AI 运行时。完成后应满足：

1. NPC 对话和世界导演可以独立配置、启停和选择模型；
2. CLI、Server 与 Godot 遵守同一套失败语义和事务边界；
3. 模型调用失败时明确报错、保留会话并回滚权威状态，不进行语义降级；
4. AI 导演的权威选择能够完整审计、保存和确定性重放；
5. 确定性门禁不依赖网络，真实模型验证通过独立入口执行；
6. AI 只能选择 Go 引擎提供的合法能力，不能直接构造 Effect 或修改世界状态。

## 2. 已完成基线

截至当前版本，以下能力已经落地：

- CLI 可以完成调查、交涉、准备、移动、等待、日志、地图、存档和结局流程；
- NPC 对话支持多轮上下文、取消、等待和重试，失败时不生成模板回复；
- 世界导演只能从内容包声明的合法指令中选择，效果仍由 Go 引擎事务结算；
- CLI 中 NPC 对话和世界导演已经具备独立开关、模型、端点、超时、输出上限和重试配置；
- CLI 世界行动支持异步等待、取消、重试和整项行动回滚；
- `director` 与 `director all` 可以查看导演理由和关注信号，普通模式不显示内部 ID；
- 存档格式 v4 使用显式、带版本且标记完整的 `director_replay` 契约；
- AI 关闭时使用确定性系统；AI 开启后，超时、空响应、结构错误和非法指令均明确失败，不允许静默降级；
- `go test ./...`、内容编译、内容测试以及三个官方内容包的验证均已进入现有门禁。

## 3. 实施原则

- 配置结构修改遵循“领域契约、静态校验、Server、客户端、测试、文档”的顺序；
- API Key 只从环境变量或安全凭据存储读取，不进入普通设置、存档、日志或诊断包；
- 资源缺失可以使用表现 fallback，AI 语义失败不得使用本地模板或确定性结果冒充模型结果；
- 所有权威状态修改必须经过 Go 引擎，模型输出只表达受限选择；
- 存档重放只消费已保存的权威决策，禁止重新请求模型；
- 确定性测试必须显式关闭 AI，真实模型测试必须使用独立入口；
- 新功能必须同时覆盖黑风谷、天启和轨道站，避免重新引入故事专属分支。

## 4. P0：统一双 AI 配置

### 目标

将 CLI 已实现的 NPC 对话与世界导演独立配置扩展到 Server API 和 Godot 设置界面。目前 Server 仍使用单一 AI 设置和服务实例，不能算端到端完成。

### 工作项

- 将 Server 的单一 `AISettings` 拆分为 `dialogue` 和 `world_director` 两个配置域；
- 两组配置分别包含启用状态、模型、端点、超时、最大输出 Token 和 SDK 重试次数；
- 更新 `/api/v1/game/settings/ai` 请求、响应和生成的 API Schema；
- 健康接口分别返回 NPC 对话、世界导演和运行时配置能力；
- Godot 设置界面分别展示和更新两组配置；
- 单项配置更新失败时保留另一项已经生效的服务；
- 启用配置必须先完成校验和服务构造，成功后再原子替换运行时；
- 更新 `.env.example`、开发文档和设置相关测试。

### 验收标准

- 可以只启用 NPC 对话或只启用世界导演；
- 可以为两者指定不同模型和超时；
- 修改一项配置不会重建或关闭另一项服务；
- 配置错误具有明确字段和错误类别，不会部分生效；
- API Key 不出现在设置响应、日志、存档或测试快照中；
- CLI、Server 和 Godot 对同一配置给出一致的能力状态。

## 5. P0：贯通取消与事务回滚

### 目标

让 Server 和 Godot 具备与 CLI 一致的取消、错误恢复和整项行动事务边界。

### 工作项

- 将 HTTP 请求的 `context.Context` 传递到 Session、Engine 和模型 SDK；
- Godot 支持主动取消正在执行的世界行动；
- 客户端断开、请求取消或超时时，中止模型调用并回滚整项玩家行动；
- 统一 `cancelled`、`timeout`、`provider_error`、`empty_response`、`schema_error` 和 `invalid_directive` 错误类型；
- 失败后保留当前 Session，提供明确的重试入口；
- 避免模型请求长期持有 Server 全局锁，确保健康检查和只读设置查询仍可响应；
- 同一 Session 同时只允许一个权威行动结算，拒绝并发写入；
- 增加取消发生在模型调用前、调用中和返回后的竞态测试。

### 验收标准

- 取消跨越多天的 `wait next` 后，日期、玩家状态、世界状态、行动历史和指标全部恢复；
- 模型错误不会关闭 CLI、Server 或 Godot 游戏会话；
- 重试只重新执行原始权威行动，不复用失败结果；
- 请求取消后没有迟到的 goroutine 修改世界状态；
- 健康检查不会因另一个模型请求而长时间阻塞。

## 6. P0：完善导演审计与重放完整性

### 目标

使导演存档既能保证权威指令重放，也能作为可信的模型调用审计记录。

### 工作项

- 扩展导演决策元数据：Provider 类型、实际模型、请求 ID、输入/输出 Token、耗时和 Prompt/Schema 版本；
- 移除固定的 `anthropic` 来源标记，兼容 StepFun 等 Anthropic Messages 兼容服务；
- 普通玩家界面只显示“AI 模型”或“确定性规则”，详细元数据仅在调试和诊断界面展示；
- 存档重放比较完整规范字段，包括触发器、分数、描述、关注信号、世界信号和事件 ID；
- 校验日期严格递增、同日决策唯一、来源非空、日期不越界和记录数量上限；
- 校验保存的指令在对应重放日期确实属于合法候选；
- 区分“实时模型决策”和“从存档重放的模型决策”，加载时不发起网络请求；
- 为缺失、空数组、重复日期、篡改指令和篡改审计字段增加负向测试。

### 验收标准

- 修改任一权威决策字段都会导致存档加载失败；
- 删除某日决策不会触发确定性选择，而是明确报告重放记录缺失；
- 使用 StepFun 时审计不再错误显示为 Anthropic 原生服务；
- 日志和诊断包可以定位模型请求，但不包含 API Key、Authorization 或完整敏感配置。

## 7. P1：建立真实模型专项门禁

### 目标

在不影响确定性 CI 的前提下，持续验证实际 Anthropic 兼容模型链路。

### 工作项

- 新增 `tools/verify-ai.ps1`，支持 `dialogue`、`director` 和 `all` 三种目标；
- NPC 对话验证多轮上下文、结构化输出、引用事实和建议行动；
- 世界导演验证合法候选选择、审计写入、存档保存和加载重放；
- 使用可控 Mock Transport 覆盖超时、空响应、Schema 错误、非法 ID 和 Provider 4xx/5xx；
- 真实网络测试只验证成功链路和敏感信息保护，不进入普通 `verify.ps1`；
- 生成脱敏测试报告，记录 Provider、模型、耗时和 Token，不保存完整模型响应。

### 验收标准

- 无 API Key 时专项门禁明确跳过或报告未配置；
- 普通 Go/Godot 门禁完全不依赖网络；
- 真实模型失败不会掩盖为成功，也不会阻断与 AI 无关的确定性验证；
- 测试输出经过自动扫描，不包含 API Key 和 Authorization 请求头。

## 8. P1：让 NPC 对话形成受约束的游戏入口

### 目标

在不允许模型直接改写世界的前提下，让自然语言对话更顺畅地连接权威行动。

### 工作项

- 模型只能建议当前 `AvailableActions` 中存在的行动 ID；
- CLI 与 Godot 展示建议行动的玩家文案、条件、成本、风险和预期结果；
- 增加 `accept` 或等价的预览操作，玩家再次确认后才执行；
- 执行前由 Go 应用层重新校验行动仍然可用；
- 状态变化导致建议过期时明确拒绝，不自动替换为其他行动；
- 建议失败或无合法建议时保持纯对话，不构造虚假行动。

### 验收标准

- 模型不能建议未提供给它的行动；
- 接受建议仍走普通 Session/Engine 事务和存档流程；
- 对话本身不推进时间，也不直接修改资源、关系、物品或结局；
- 迟到的建议不会在状态版本变化后执行。

## 9. P1：持久化非敏感运行设置

### 目标

让用户重启后保留常用设置，同时严格隔离密钥。

### 工作项

- 保存两类 AI 的开关、模型、端点、超时、Token 和重试次数；
- 保存默认世界、存档目录和自动存档开关；
- 明确环境变量、命令行参数、用户设置和内置默认值的优先级；
- CLI 与 Godot 使用同一字段契约和校验逻辑；
- API Key 继续从环境变量或平台安全凭据读取，不写入普通设置文件；
- 设置文件损坏时明确报错并允许用户修复，不静默套用故事语义默认值。

### 验收标准

- 重启后非敏感设置保持一致；
- 命令行临时覆盖不会意外改写持久设置；
- 设置文件和诊断导出中不存在 API Key；
- 旧设置无法安全迁移时明确要求用户重新配置。

## 10. P2：终端产品体验

在运行时和存档契约稳定后，再进行终端体验升级：

- 启动时列出并选择可用世界，不要求记忆 `-data` 路径；
- 增加命令历史、方向键导航和人物、地点、行动名称补全；
- 优化模型等待进度、取消状态和排队输入提示；
- 为导演审计增加分页、过滤和脱敏导出；
- 保留纯 stdin/stdout 脚本模式，TUI 不得破坏自动试玩和 CI；
- 存档列表应隔离损坏槽位，单个无效存档不影响其他槽位展示。

## 11. P2：内容与机制多样性验证

轨道站已经验证了资源名和世界术语的可替换性，但其核心机制仍与黑风谷接近。后续应加入一个机制差异更大的小型世界，例如经营债务、城市刑侦或空间站危机，要求：

- 只新增 `data/<world>` 和可选表现资源；
- Go 与 GDScript 不增加世界、人物、地点和 Flag 专属分支；
- CLI 与 Godot 均可完整通关、保存、加载和批量模拟；
- 使用不同的资源体系、行动类型、时间压力和结局条件；
- 正式内容包进入内容编译、图检查、批量模拟和 Godot 可移植性门禁。

## 12. 推荐实施顺序

| 顺序 | 阶段 | 依赖 | 完成标志 |
| --- | --- | --- | --- |
| 1 | 双 AI 配置贯通 | 当前 CLI 配置模型 | Server、Godot 可独立配置两项服务 |
| 2 | Server/Godot 取消与事务 | 双配置运行时 | 取消、超时和失败均保留会话并完整回滚 |
| 3 | 审计与重放强化 | 稳定的运行时元数据 | 存档和诊断能完整验证每次导演选择 |
| 4 | 真实模型专项门禁 | 稳定错误分类和审计 | 成功与主要失败模式均可独立复现 |
| 5 | 对话建议行动 | API 与事务稳定 | 自然语言建议可安全进入权威行动确认流程 |
| 6 | 设置持久化 | 双配置字段稳定 | CLI/Godot 重启后保留非敏感设置 |
| 7 | 终端体验与第三世界 | 核心契约稳定 | 产品体验提升且新世界保持零代码分支 |

## 13. 阶段完成定义

每个阶段只有同时满足以下条件才视为完成：

1. 领域结构、API Schema、Server、CLI/Godot、测试和文档同步更新；
2. `go test ./...` 与 `./tools/verify.ps1` 通过；
3. 涉及 Godot 时，`./tools/verify-godot.ps1` 在明确关闭 AI 的模式下通过；
4. 涉及真实模型时，独立 AI 门禁记录成功、失败和脱敏检查结果；
5. 至少两个内容包完成运行验证，通用代码没有新增故事专属分支；
6. 新增配置在场景或服务初始化阶段完成校验，不延迟到首次使用；
7. 模型关闭、失败、取消、重试、保存和加载路径均有自动测试；
8. 提交不包含 `.env`、API Key、真实模型完整响应、运行日志、临时存档或录制产物。

## 14. 明确不采用的方向

- 不让世界导演直接生成任意 Effect；
- 不让 NPC 对话直接修改资源、关系、物品、Flag 或结局；
- 不在模型失败时使用模板、缓存、旧回复或确定性选择伪装成功；
- 不把 API Key 保存到游戏设置或存档；
- 不为兼容旧配置长期维护隐式默认文案或双字段读取；
- 不在核心事务和契约尚未稳定时优先重写 TUI 或大规模扩写剧情。
