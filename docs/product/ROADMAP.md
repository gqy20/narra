# 凡途当前路线图

> 状态：唯一有效的当前计划
> 基线日期：2026-08-04
> 历史计划：见 [`../archive/plans/`](../archive/plans/)

## 当前基线

仓库已经具备以下可运行能力：

- `blackwind`、`tianqi` 与可移植性测试世界 `orbital` 均进入内容编译和 Godot 门禁；
- Go 内核提供确定性结算、内容校验、批量模拟、存档回放和本地 API；
- Godot 已形成可完整通关的地图、地点、人物、行动、卷宗、演出和结局流程；
- 人物对话和世界导演可以显式启用 AI，关闭时不会发起模型请求，失败时不会伪造降级结果；
- 字体、语义色、通用控件与游戏屏幕区域已完成分层；
- Windows 与 macOS 打包、GitHub CI/Release、日志诊断、标准录制和跨内容包验证已有自动化入口。

## P0：外部可玩性验证

目标是确认新玩家不依赖开发者解释也能理解目标、时间压力、路线代价和行动后果。

- 使用固定版本和独立存档完成至少一轮外部试玩；
- 记录首次迷失点、误判原因、不可逆选择理解度和结局可解释性；
- 将发现的问题转成可复现断言或固定场景截图；
- 不以新增系统代替信息层级和反馈问题的修复。

完成标准：试玩报告包含版本、内容包、路线、证据和复验结果，高优先级问题进入自动化回归。

## P0：天启内容与运行事实对齐

- 逐项核对叙事文档、研究边界与 `data/tianqi` 的人物、证据、地点和路线；
- 删除只存在于文档但已不再采用的实现假设；
- 玩家可见文本不泄露内部人物、事实、动作或策略 ID；
- 新增史实引用前完成来源等级和使用边界复核。

完成标准：天启文档导航能够指出每项设计在运行内容中的对应位置，差异有明确的“计划中”标记。

## P1：视觉与交互回归产品化

- 固化 1280×800 与 1920×1080 的关键界面截图基线；
- 覆盖开始页、地图、地点、人物聚焦、卷宗、确认和结局；
- 检查字号、对比度、键盘焦点、缩放和长文本边界；
- 将资源缺失的视觉降级与语义配置错误继续严格区分。

完成标准：视觉修改可通过固定路线复验，不依赖单张人工截图印象。

## P1：真实模型专项门禁

- 独立覆盖成功、超时、取消、空响应、结构错误、越权内容和提供方错误；
- 分别验证人物对话与世界导演，不复用确定性门禁的结果；
- 确认密钥、Authorization 和完整敏感配置不进入日志或诊断包；
- 保存导演权威决策并在读取存档时重放，不重新请求模型。

完成标准：非确定性测试有独立入口和报告，失败不阻断与 AI 无关的确定性门禁。

## P2：内容生产与发布效率

- 为新世界提供最小模板、内容图、批量模拟和可移植性验收说明；
- 缩短正式资源接入、截图、录制和 Windows 发布的人工步骤；
- 用文档链接检查和状态标记阻止历史计划重新混入当前规范。

## 暂不扩张

在 P0 完成前，不把战斗、队伍、技能树、大地图或新的 AI 权限作为主线工作。任何新系统都必须先证明它解决了已观察到的玩家决策问题。
