# Narra 当前路线图

> 状态：唯一有效的当前计划
> 基线日期：2026-08-05
> 历史计划：见 [`../archive/plans/`](../archive/plans/)

## 当前基线

仓库已经具备以下可运行能力：

- `blackwind`、`tianqi` 与可移植性测试世界 `orbital` 均进入内容编译和 Godot 门禁；
- Go 内核提供确定性结算、内容校验、批量模拟、存档回放和本地 API；
- Godot 已形成可完整通关的地图、地点、人物、行动、卷宗、演出和结局流程；
- 人物对话和世界导演可以显式启用 AI，关闭时不会发起模型请求，失败时不会伪造降级结果；
- 字体、语义色、通用控件与游戏屏幕区域已完成分层；
- Windows 与 macOS 打包、GitHub CI/Release、日志诊断、标准录制和跨内容包验证已有自动化入口。

## P0：外部可玩性验证

目标是确认新玩家不依赖开发者解释也能理解目标、时间压力、路线代价和行动后果。

- 使用固定版本和独立存档完成至少一轮外部试玩；
- 记录首次迷失点、误判原因、不可逆选择理解度和结局可解释性；
- 将发现的问题转成可复现断言或固定场景截图；
- 不以新增系统代替信息层级和反馈问题的修复。

完成标准：试玩报告包含版本、内容包、路线、证据和复验结果，高优先级问题进入自动化回归。

## P0：天启内容与运行事实对齐

- 逐项核对叙事文档、研究边界与 `data/tianqi` 的人物、证据、地点和路线；
- 删除只存在于文档但已不再采用的实现假设；
- 玩家可见文本不泄露内部人物、事实、动作或策略 ID；
- 新增史实引用前完成来源等级和使用边界复核。

完成标准：天启文档导航能够指出每项设计在运行内容中的对应位置，差异有明确的“计划中”标记。

## P1：视觉与交互回归产品化

- 固化 1280×800 与 1920×1080 的关键界面截图基线；
- 覆盖开始页、地图、地点、人物聚焦、卷宗、确认和结局；
- 检查字号、对比度、键盘焦点、缩放和长文本边界；
- 将资源缺失的视觉降级与语义配置错误继续严格区分。

完成标准：视觉修改可通过固定路线复验，不依赖单张人工截图印象。

## P1：卷宗知识图谱与渐进披露

目标是把卷宗中依赖关系阅读的长文本改造成玩家知识图谱。默认画面只保留节点、连线、简短名称和少量状态；玩家点击一个节点后，再在固定详情区查看来源、证据、人物、期限、影响和可执行入口。

这不是把所有卷宗信息都画成点和线。人物、证据、说法、事件、地点和路线之间的关联适合进入图谱；资源数量、综合准备度、明确阻塞条件和当前行动建议仍应留在摘要或节点详情中，避免用图形重新制造信息噪音。

### 玩家视图

- 默认只显示玩家已经获知的节点与关系，不显示事实真值、NPC 私有认知、隐藏计划、内部评分或未发现路线；
- 节点只常驻名称、类别和一个关键状态，关系标签只在选中、悬停或键盘聚焦时展开；
- 同一时间只打开一个焦点详情，详情包含简短结论、获知来源、相关对象、变化记录、剩余疑点和当前可用行动；
- 新获得或发生变化的节点使用短时动效提示，已读后回到稳定语义色，不让整张图持续闪烁；
- 图谱支持平移、缩放、适应视图、按类别筛选和名称搜索，并提供不依赖鼠标的节点遍历与详情开关；
- 1280×800 下优先保证节点与详情可读，1920×1080 下可以显示更多关系，但不得依赖极小字号扩大容量。

### 信息结构与契约

- 应用层从权威世界状态投影只读的玩家知识图谱，Godot 不根据文案、颜色或本地规则猜测关系；
- 节点至少区分人物、证据、公开说法、事件、地点和路线，具体名称及玩家文案由内容包提供；
- 关系包含稳定类型、玩家可见标签、方向、发现时间和可选摘要，不把内部事实 ID、人物 ID 或策略 ID 显示给玩家；
- 节点详情引用现有人物档案、证据材料和路线进度，避免为图谱复制第二份互相漂移的故事数据；
- 图谱必须同时通过《凡途》《天变邸抄》和《远星环站》的可移植性验证，通用 Go/GDScript 不增加故事专属分支；
- AI 不负责凭空补关系。模型生成的 NPC 表达只有经过既有权威规则确认并成为玩家已知信息后，才能进入图谱。

### 分阶段实现

1. **信息审计与静态原型**：以当前随身卷宗为基线，标记哪些句子属于节点、关系、状态、摘要或详情；分别用《天变邸抄》和《凡途》制作一张固定数据原型，验证默认密度与点击展开方式。
2. **只读图谱**：增加玩家知识图谱投影和 API 契约，在 Godot 中实现节点、连线、单焦点详情、筛选、搜索与键盘访问；原卷宗保留为稳定回退。
3. **动态变化**：接入调查、传话、人物决断、路线变化和新证据，使新增关系与状态变化能够被定位、解释和回放，但不让动画阻塞玩家操作。
4. **规模与回归**：覆盖多路线并行、近似重名、长标题、孤立节点、关系环、大量已读节点和资源缺失；确定节点上限、聚类规则与降级列表模式。

### 当前试作进度

- 已完成玩家可见信息到 `PlayerView.knowledge_graph` 的只读投影，节点和关系只来自现有公开视图，不读取事实真值、NPC 私有认知或隐藏计划；
- 已完成 Godot 卷宗“图谱”页、稳定分栏布局、类别筛选、单焦点详情、方向键遍历，以及从详情提交现有公开行动；原有卷宗标签继续保留；
- 已用《凡途》和《天变邸抄》覆盖跨内容包投影测试，并验证不可见线索不会进入图谱；
- 已完成 1280×800 与 1920×1080 的说法、人物和地点聚焦状态截图检查，并用集成测试覆盖默认态与类别筛选；
- 下一步补齐证据与说法的内容契约区分、名称搜索、平移缩放、变化提示与回放，并覆盖《远星环站》、空图和高密度图。

### 验收标准

- 新玩家能在 30 秒内指出“这条证据关联谁”“当前路线卡在哪里”“最近哪项关系发生变化”；
- 默认态不展开长段正文，不铺满关系标签，选中态只出现一个焦点详情；
- 图谱与原卷宗对同一玩家状态表达的信息完整一致，不泄露任何未获知信息；
- 切换内容包不需要修改图谱代码，缺少可选布局提示时仍能得到稳定可读的自动布局；
- 1280×800 与 1920×1080 固定场景截图覆盖默认、聚焦、筛选、新增节点、空图和高密度图；
- 自动化断言覆盖节点与边引用、重复关系、不可见信息过滤、焦点唯一性、键盘可达性和详情来源一致性。

首版不提供玩家编辑节点、自由绘制连线、3D 图谱、全屏粒子动画或由 AI 自动推断“真相”。知识图谱也不替代地点地图、行动区和所有卷宗标签，只负责让关系密集的信息更容易浏览和追溯。

## P1：真实模型专项门禁

- 独立覆盖成功、超时、取消、空响应、结构错误、越权内容和提供方错误；
- 分别验证人物对话与世界导演，不复用确定性门禁的结果；
- 确认密钥、Authorization 和完整敏感配置不进入日志或诊断包；
- 保存导演权威决策并在读取存档时重放，不重新请求模型。

完成标准：非确定性测试有独立入口和报告，失败不阻断与 AI 无关的确定性门禁。

## P2：内容生产与发布效率

- 为新世界提供最小模板、内容图、批量模拟和可移植性验收说明；
- 缩短正式资源接入、截图、录制和 Windows 发布的人工步骤；
- 用文档链接检查和状态标记阻止历史计划重新混入当前规范。

## 暂不扩张

在 P0 完成前，不把战斗、队伍、技能树、大地图或新的 AI 权限作为主线工作。任何新系统都必须先证明它解决了已观察到的玩家决策问题。
