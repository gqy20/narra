# 交互 Demo 试玩优化清单

> 本清单记录 2026-07-31 对 `cmd/play` 的首次人工试玩结果。它只处理现有冻结范围内的可玩性阻塞，不新增战斗、队伍、任务、技能树或正式 Godot UI。

## 1. 目标与完成定义

当前 Demo 需要验证：

> 玩家能否依据不完整情报进行核验、准备和传播，并通过这些选择改变黑风谷局势，同时理解结果为什么发生。

优化完成后，新玩家应当能够：

* 不读代码或自动测试即可理解当前目标、关键时间和主要阻塞；
* 在每个回合辨认“世界发生了什么、与自己有什么关系、下一步能做什么”；
* 理解为什么要选择某名 NPC 作为情报接收者；
* 在情报路线、准备路线和旁观路线之间做出有意识的选择；
* 在结局前感知自己的行动已经改变 NPC 决策，而不是只在终局报告中得知；
* 不需要连续输入大量没有新决策的 `wait`。

状态说明：`待实现`、`进行中`、`待人工验证`、`已验证`。只有同时具备自动测试和人工试玩证据时，体验项才标记为 `已验证`。

## 2. 当前试玩基线

| 路线 | 实际结果 | 暴露的问题 |
| --- | --- | --- |
| 盲玩与错误恢复 | 无效编号不会推进时间；核验可以纠正错误日期并产生新线索 | 首屏术语多；行动列表在核验后膨胀；人物缺少选择依据 |
| 情报传播 | 第 4 天把 F01 告诉沈砚秋，最终由沈砚秋取得青髓芝 | 30 天中只有 3 次主动行动、27 次等待；影响过程直到结局才解释 |
| 战力准备 | 不核验情报，买药并连续修炼五次即可由玩家取得青髓芝 | 重复修炼成为最直观的稳定解，削弱情报核心玩法 |
| 旁观路线 | 世界能够自行推进并形成结果 | 玩家长期只能看到“一天过去”，动态世界存在但不可感知 |

工程基线：统一验证脚本通过；`internal/app` 覆盖率 90.8%，`internal/engine` 覆盖率 84.7%。

## 4. P0：核心闭环阻塞

### 本轮已落地的最小改动

* 默认 CLI 已本地化资源、状态和调查来源；事实 ID 与行动 ID 只在 `-debug` 模式显示。
* 玩家情报触发 NPC 反事实变化时，当天即展示“原本会做什么、现在改做什么”。
* 核心归属产生后，交互流程立即展示结局，不再要求继续输入到第 30 天；旧版存档中的后续历史仍可回放。
* `PlayerView.Metrics` 已记录决策输入、主动行动、等待、最大目录、最长空等待、重复主动行动、可见决策变化、核心结果日和结果后输入。
* 忙碌时可直接推进到行动完成；空闲时可推进到下一个实际决策点，期间的公开事件会合并展示。
* 路线提示已拆分物品、开放状态、总旅行时间和基于玩家当前认知的最晚出发判断。

以上项目已有自动测试，仍需人工试玩后才能按本文状态规则标记为 `已验证`。

### PT-01 每日局势摘要与可见因果反馈

**问题证据**

* `PlayerView` 已提供 `Phase`、`RecentEvents` 和人物阵营，但 CLI 没有完整展示。
* 情报送达后只提示“情报已经送达”，玩家直到第 30 天才知道它在第 5、17、19 天改变了沈砚秋的首选行动。
* NPC 离开当前位置、开始准备或改变计划时缺少解释。

**实现范围**

* 在状态头部展示当前局势阶段和距已知关键日期的剩余时间。
* 在每回合反馈后增加“今日局势”区，只列出新发生且玩家可知的事件。
* 将玩家触发的反事实变化转译为具体结果：谁放弃了什么、改做了什么、原因是什么。
* 当同地人物变化时，说明已知的到达或离开事件；没有合理信息来源时不泄露后台状态。
* 不重复展示已经确认过的旧事件。

**验收标准**

* [x] 玩家传播 F01 后，最迟在沈砚秋首次改变行动时看到一条具体反馈。
* [x] 反馈包含人物、旧计划或原意、新计划以及与玩家情报的关系。
* [ ] 旁观路线每个重要阶段至少出现一条可见局势变化，不连续输出十次相同的“一天过去”。
* [ ] CLI 不展示 NPC 私有认知、内部评分、世界标记或真实日期等未获知信息。
* [ ] `RecentEvents`、`Phase` 和人物阵营具有对应的 CLI 渲染测试。

**可能涉及**

* `cmd/play/main.go`
* `internal/app/session.go`
* `internal/app/feedback.go`
* `internal/app/types.go`

### PT-02 路线条件与时间窗口提示

**问题证据**

第 0～16 天持续显示“通往黑风谷的条件尚未齐备”，但没有区分缺少解瘴丹、路线尚未开放或旅行时间不足。第 17 天路线直接出现在行动列表中。

**实现范围**

* 将模糊提示拆成已满足条件、未满足条件和可观察的窗口信号。
* 显示从当前位置到目标地点的总旅行耗时。
* 当玩家已知日期与旅行耗时形成风险时，给出“现在出发是否来得及”的判断，但不泄露未知日期。
* 在路线开放前通过世界事件逐步预告参与者集结、封锁松动或入口开放。

**验收标准**

* [x] 没有解瘴丹时明确显示需要解瘴丹。
* [x] 已有解瘴丹但路线未开放时，明确显示剩余阻塞来自路线状态。
* [x] 第 17 天之前至少出现一次可观察的路线开放预兆。
* [x] 已核验真实日期的玩家能够仅凭界面判断最晚出发时间。
* [x] 未核验日期的玩家只获得风险提示，不被告知真实成熟日。

**可能涉及**

* `internal/app/feedback.go`
* `internal/app/catalog.go`
* `internal/app/session_test.go`
* `data/blackwind/locations.json`

### PT-03 压缩无决策等待

**问题证据**

* 两日核验需要先执行核验，再手动输入一次 `wait`。
* 三日修炼需要额外输入两次 `wait`。
* 情报传播路线 30 天中有 27 次等待。
* 核心争夺在第 21 天结束后，仍需等待到第 30 天才能看到总结。

**实现范围**

* 增加 `wait-until` 类能力：等待到当前行动完成、下一个可见事件或指定日期。
* 持续行动期间若没有可见事件或可响应选择，允许自动推进到完成日。
* 发生重要事件、路线变化、市场变化或行动失败时中断自动推进。
* 核心争夺结束后立即提供“查看结局”；继续观察余波改为可选项。

**验收标准**

* [x] 完成一次核验最多需要两次决策输入，不需要逐日确认。
* [x] 完成一次三日修炼不需要连续输入两个相同的 `wait`。
* [x] 传播路线从开始到看到核心结果的输入次数较当前基线下降至少 50%。
* [x] 自动推进遇到新决策点、玩家因果反馈或核心结果时停止，期间公开事件合并展示，并在存档回放后保持确定性一致。
* [x] 第 21 天结果产生后，可以立即进入完整结局总结。
* [x] 手动逐日 `wait` 仍可用于调试、测试和旧存档回放。

**可能涉及**

* `cmd/play/main.go`
* `internal/app/session.go`
* `internal/app/feedback.go`
* `internal/app/save.go`

### PT-04 重新平衡情报与重复修炼

**问题证据**

当前准备者路线无需核验真实日期：购买一颗解瘴丹、连续修炼五次、在路线开放后进谷，即可用准备值 7 取得青髓芝。这条路线比情报路线更容易理解和执行。

**设计约束**

* 不删除纯准备路线；它可以作为高成本的明确替代方案。
* 不通过新增复杂系统解决，优先调整现有行动收益、时间成本和信息收益。
* 不把情报变成唯一正确答案，但应让情报显著改变计划效率或风险。

**候选方案**

1. 连续修炼递减收益，或在短周期内增加恢复时间。
2. 情报可提前开放路线、减少旅行风险或提供争夺准备加成。
3. 未核验日期的玩家进入内谷时承担迟到、错误准备或竞争劣势。
4. 将“准备值”拆成玩家可理解的来源摘要，避免只有战力单项决定结果。

**验收标准**

* [ ] 不核验情报的纯修炼路线仍可获胜，但消耗显著更多时间、资源或风险承受。
* [ ] 至少一条情报路线能以更少重复行动形成可见优势。
* [ ] 单一重复行动不会在合理扰动范围内成为稳定最优解。
* [ ] 结算前可以看到自身准备值的构成，不显示 NPC 的隐藏总分。
* [ ] 批量报告增加玩家行动集中度，并对连续重复修炼给出警告阈值。

**可能涉及**

* `internal/app/catalog.go`
* `internal/engine/competition.go`
* `internal/engine/costs.go`
* `internal/batch/report.go`
* `data/blackwind/actions.json`

## 5. P1：信息组织与表达

### PT-05 压缩情报传播行动目录

**问题证据**

核验 F02 后，4 名同地 NPC 与 3 条线索组合成 12 个传播选项，总行动数达到 18 项。

**实现范围**

* CLI 交互改为先选择“告知某人”，再选择线索；底层行动 ID 保持稳定。
* 列表按调查、交涉、交易、移动、修炼、推进时间分组。
* 已经告知同一人物的相同说法默认隐藏或标记为“已告知”。
* 每组优先展示当前新增、即将过期或与提示相关的行动。

**验收标准**

* [ ] 任一主菜单同屏一级行动不超过 10 项。
* [ ] 玩家仍可直接输入完整行动 ID，保证脚本和存档兼容。
* [ ] 重复告知不会伪装成新的有效选择。
* [ ] 菜单层级支持返回且错误输入不推进时间。

### PT-06 增加人物决策上下文

**实现范围**

* 同地人物至少显示姓名、阵营和玩家已知的一句立场或近期行为。
* 选择传播对象时显示玩家能够合理知道的利益、可信度风险和关系状态。
* 不知道的信息明确标记为“尚不了解”，而不是留空或暗示后台真值。

**验收标准**

* [ ] 首次传播情报前，玩家可以说出至少两名候选人的可见差异。
* [ ] 人物摘要只来自公开资料、同地观察和玩家已获得的线索。
* [ ] 自动测试验证人物摘要不会泄露目标权重、私有信念和策略评分。

### PT-07 玩家术语本地化

**替换范围**

| 内部显示 | 玩家显示 |
| --- | --- |
| `combat` | 战力 |
| `support` | 支援 |
| `spirit_stones` | 灵石 |
| `credit` | 信誉 |
| `started` / `progressing` / `completed` | 已开始 / 进行中 / 已完成 |
| `player-investigation` | 亲自核验 |
| `player-investigation-lead` | 调查所得线索 |

事实 ID、行动 ID 和内部来源保留在调试模式或方括号次级信息中。

**验收标准**

* [x] 默认 CLI 不出现未解释的英文资源键、状态或来源字符串。
* [x] 调试模式仍能查看稳定 ID，方便复现问题。
* [x] 存档和数据结构不因展示名称变化而改变。

### PT-08 终局故事化总结

**实现范围**

终局按以下顺序组织：

1. 核心结果；
2. 玩家最重要的三个选择；
3. 这些选择造成的可证明变化；
4. 错过的机会或承担的代价；
5. 最终人物状态和可继续发展的余波。

重复出现的同类反事实变化应合并为一条因果链，避免连续列出“第 5、17、19 天改变首选行动”而不说明变化内容。

**验收标准**

* [ ] 旁观、求真、传播和准备四条路线生成明显不同的总结。
* [ ] 总结至少包含一条“因为玩家做了 X，所以人物或局势发生 Y”的具体句子。
* [ ] 没有产生实际影响的情报只描述为送达，不宣称改变了决策。
* [ ] 结局保留可调试的统计附录，但统计不再是主叙事。

## 6. P2：可读性与持续验证

### PT-09 终端可读性与无障碍风险

**实现范围**

* 默认只打印本回合变化和下一步建议，完整状态通过 `status` 命令查看。
* 为行动列表提供稳定分组标题和一致阅读顺序。
* 在 80 列终端下避免核心信息被迫横向滚动。
* 不只依靠颜色表达可信度、危险度、完成状态或警告。
* 对长列表提供分页或筛选，但确保纯键盘可以完成所有核心流程。

**验收标准**

* [ ] 80×24 终端能够看清回合反馈和首要行动，不需要横向滚动。
* [ ] 关闭颜色后所有状态仍可辨认。
* [ ] 使用顺序读取输出时，标题、变化、提示、行动的顺序符合决策过程。
* [ ] 所有核心命令均有文字标签和键盘路径。

### PT-10 新增可玩性指标

应用层已经记录下列最小指标，并在终局输出决策输入、主动行动、推进次数、自动略过天数和核心结果日。传播路线由 21 次输入降至 8 次，自动略过 18 天；旁观路线最多 4 次输入即可到达核心结果。批量汇总和警告阈值仍待实现。

批量或交互报告增加：

* 玩家主动行动占比；
* 连续无事件等待天数；
* 相同行动连续重复次数；
* 首次获得关键线索到采取相关行动的天数；
* 玩家触发且对玩家可见的 NPC 决策变化数；
* 行动目录最大长度；
* 结算后仍需输入的无决策天数；
* 各路线到达核心结果所需的决策输入数。

**初始警告建议**

* 连续 5 天以上只有“等待”且没有可见新事件；
* 单一主动行动占全部主动行动的 60% 以上；
* 一级行动目录超过 10 项；
* 核心争夺结束后仍要求 3 次以上输入；
* 玩家改变 NPC 决策但连续 3 天没有任何可见反馈。

## 7. 推荐实施顺序

1. 先实现 PT-01 和 PT-02，让现有世界状态变得可读。
2. 实现 PT-03，减少人工试玩成本并暴露真正的决策密度。
3. 使用新的可玩性指标验证 PT-04，而不是凭单次路线直接调数值。
4. 完成 PT-05～PT-08，收紧信息架构和叙事反馈。
5. 最后执行 PT-09、PT-10，并组织不读代码的新玩家试玩。

每完成一个 P0 项，都至少重新跑以下四条路线：旁观者、求真者、准备者、传播者。不得只依赖现有自动测试判断体验项已经完成。

## 8. 本轮不做

* 正式 Godot UI；
* 战斗、伏击、逃亡或队伍系统；
* 新地点、新 NPC 或新局势；
* 自由对话和运行时 AI 文本；
* 借贷、联盟、复杂交易等模拟内核已有但 Demo 尚未开放的机制；
* 为了掩盖信息表达问题而增加新玩法。
