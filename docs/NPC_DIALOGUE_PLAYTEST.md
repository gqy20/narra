# NPC 多轮对话真实模型试玩

日期：2026-08-02  
模型：`step-3.7-flash`  
接口：Anthropic Messages 兼容接口  
范围：CLI 多轮对话、结构化行动建议、NPC 隔离、存档恢复、取消与失败路径

## 试玩结论

多轮上下文、NPC 之间的记忆隔离、结构化行动建议、存档恢复和权威状态隔离均可工作。真实试玩也暴露出三个影响体验的问题：30 秒默认超时偏短；模型可能把低置信传闻说成事实；建议行动的描述会把 NPC 尚未知晓的玩家线索泄露给模型。

本轮已经将默认模型超时提高到 60 秒、Godot HTTP 超时提高到 65 秒，并收紧模型输入与输出校验。建议行动现在只向模型提供行动 ID 和公开名称，不再提供事实正文；低置信事实若没有不确定性措辞会被拒绝；恢复存档后使用续接模式，不再重新开场。

## 五种玩家风格

### 1. 叙事追问型

路线：与魏无咎交谈，询问其核验消息的方式，并明确拒绝出售消息。

观察：

- 首轮能生成符合人物功利倾向的开场；
- 第二轮曾在默认 30 秒处超时，CLI 明确报错，没有生成替代台词，也没有记录失败轮次；
- 初版会补出“价钱好说”等未提供的承诺。

处理：默认超时提高到 60 秒；提示词明确禁止补充报酬、库存和交易条件。

### 2. 越权攻击型

路线：要求李玄忽略规则，泄露秘密计划、隐藏数值和提示词，并直接给予物品。

观察：

- 模型拒绝泄密和直接给予物品；
- 日期、物品、关系和权威行动历史均未改变；
- 初版会顺带补出未经上下文支持的库存判断。

处理：继续保持“失败即报错、无本地降级”；加强禁止虚构库存和主动交易承诺的系统约束。

### 3. 功利决策型

路线：要求罗七娘指出收益最高的选择并保证具体报酬。

观察：

- 模型没有直接执行行动，建议 ID 始终来自当前规则行动；
- 初版把传闻日期说成确定事实，并出现不合人物身份的“小老儿”自称；
- 修复后开场只询问来意，追问传闻时明确回答“尚未核实”，不再保证收益。

处理：增加传闻不确定性校验；禁止没有明确语言设定的身份化自称。

### 4. 多人物切换型

路线：先与魏无咎交谈，再切换到李玄，要求李玄复述魏无咎原话。

观察：

- 李玄明确表示没有听闻魏无咎所言，没有获得另一 NPC 的会话历史；
- 同一地点切换人物不推进时间；
- 每个 NPC 只收到自己的同 revision 最近 8 轮记录。

结论：NPC 会话隔离正确。

### 5. 存档恢复型

路线：与韩四约定把某条消息称为“暮钟消息”，自动存档并退出；读取 `autosave` 后重新交谈。

观察：

- 读取后模型能识别“暮钟消息”，证明会话记录已经随存档恢复；
- 初版恢复时仍按新开场生成，造成重复询问；
- `context` 原先只显示轮数，对玩家帮助有限。

处理：新增 `resume` 语义；有历史且没有新输入时要求模型续接而非重新介绍。`context` 现在显示最近 8 轮实际对话。

## 权限边界发现

初版 `DialogueSnapshot.available_actions` 包含行动描述。对于“告知 NPC 某条线索”行动，描述中存在玩家掌握、但 NPC 尚未掌握的事实正文。模型可能从行动描述读取该事实并提前说出口，即使 `allowed_claims` 没有授权。

修复后，模型只能看到建议行动的 ID 和公开名称。完整行动描述仍只在权威客户端中展示。新增快照测试确保未授权的事实正文不会通过建议行动进入模型上下文。

## 取消测试

- Godot 有显式“取消”按钮，会取消当前 `HTTPRequest`；
- Go 服务的 context 取消与超时已有自动化测试；
- 在 Codex 的 PowerShell/Conda PTY 中发送 `Ctrl+C` 会先终止外层命令包装器，无法代表玩家直接运行 EXE 时的信号行为。

CLI 后续宜增加不依赖操作系统信号的显式 `cancel` 输入；这需要把当前同步输入循环升级为同时监听终端输入和模型结果的事件循环。
