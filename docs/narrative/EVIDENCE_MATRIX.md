> 更新日期：2026-08-03  
> 配套文档：[主线大纲](./STORY_OUTLINE.md) · [人物小传](./CHARACTERS.md) · [史料索引](../research/tianqi/SOURCES.md)

## 1. 设计原则

本作不把证据设计成“收集齐碎片后自动解锁真相”。每一项证据都必须区分：

- 物件或证词本身是否真实；
- 它实际支持什么命题；
- 人物认为它支持什么命题；
- 它在传播中被写成了什么；
- 谁保管原件，谁只见过抄件；
- 它能否经受另一来源的交叉验证。

最重要的逻辑边界是：

> 能证明王恭厂存在长期积弊，不等于能证明这些积弊直接引发五月初六的灾变。

## 2. 证据数据模型

每项证据建议使用以下字段：

| 字段 | 含义 |
| --- | --- |
| `id` | 稳定证据编号 |
| `kind` | 文书、物件、证词、观察、行政统计或推断 |
| `origin` | 原始形成者与形成时间 |
| `historicity` | 史实锚点、制度推演、完全虚构 |
| `original_holder` | 初始原件持有人 |
| `current_holder` | 当前原件持有人 |
| `copies` | 抄件持有人及抄写误差 |
| `integrity` | 完整、残缺、污染、补造、来源不明 |
| `provenance` | 保管和转手记录 |
| `supports` | 直接支持的有限命题 |
| `does_not_support` | 容易被误用但实际无法证明的命题 |
| `verification` | 可交叉验证的方法 |
| `expiry` | 现场、证人或行政窗口的失效时间 |
| `exposure` | 公开后对持有人和证人的风险 |
| `public_claim` | 当前流通版本对它的描述 |

## 3. 状态变化

一项证据可以同时拥有“物理状态”和“认知状态”。

### 3.1 物理状态

`未发现 → 原件取得 → 抄录 → 转手 → 扣押/封存/销毁`

原件被毁不应自动删除已经形成的抄件和人物记忆；抄件存在也不等于能够证明原件来源。

### 3.2 认知状态

`传闻 → 见过 → 初步核实 → 交叉印证 → 有争议 → 被推翻`

“被推翻”只针对具体命题。例如 E05 可以推翻“当夜没有车辆出入”，却不能因此证明车辆装的是火药。

### 3.3 传播状态

`私有 → 有限共享 → 奏疏引用 → 官档采用 → 抄报传播 → 街巷变体`

传播范围越大，不自动意味着可信度越高；同样，官档采用也只表示行政认可，不表示系统确认其客观为真。

## 4. E01～E10 详细矩阵

### E01 周良辅交割残页

| 项目 | 内容 |
| --- | --- |
| 类型 | 残缺文书，完全虚构 |
| 初始形成 | 灾前军需交割副册中的一页 |
| 初始持有人 | 序章中落到玩家可及区域 |
| 完整性 | 仅保留批次、日期、数量尾数和一枚异常领讫戳 |
| 直接支持 | 某批记录存在格式或流转异常 |
| 不能支持 | 该批实物仍在厂内；该批实物导致爆炸；戳记一定伪造 |
| 验证方法 | 与 E03 凭单、其他正常印戳、书办笔迹比较 |
| 争夺者 | 会勘官署、书坊、军需灰网 |
| 截止窗口 | 第 3 日起官署收缴民间捡拾文书，持有风险上升 |
| 常见误用 | 被陈言网络写成“军器尽遭侵盗”的证明 |

### E02 会勘库存抄数

| 项目 | 内容 |
| --- | --- |
| 类型 | 灾后行政统计，虚构数字、史实制度背景 |
| 初始形成 | 会勘人员对可见残存官物的清点 |
| 初始持有人 | 裴慎行所在的会勘官署 |
| 完整性 | 形式完整，但受现场破坏和时间限制 |
| 直接支持 | 灾后查得多少可识别、可归类官物 |
| 不能支持 | 爆炸前的精确库存；所有被毁和飞散物的总量 |
| 验证方法 | 搬运记录、现场区域、后续安民厂接收数 |
| 争夺者 | 会勘官署、兵部相关人员、陈言网络 |
| 截止窗口 | 军器搬离后现场无法重复清点 |
| 常见误用 | 用灾后余数反推精确爆炸当量 |

### E03 京营领取凭单

| 项目 | 内容 |
| --- | --- |
| 类型 | 交割凭证，制度推演、内容虚构 |
| 初始形成 | 灾前例行领取流程中的凭单 |
| 初始持有人 | 一名虚构京营书吏，后由郑怀朴获得抄件 |
| 完整性 | 文面完整，实物流转未必完整 |
| 直接支持 | 某批物资在账面上已被领讫 |
| 不能支持 | 领取数量真实；物资确已离厂；领取者参与假账 |
| 验证方法 | E01 戳记、E05 车辆证词、领用后的营内记录 |
| 争夺者 | 陈言网络、会勘官署、军需灰网 |
| 截止窗口 | 第 10 日前可查原经手人，此后可能被调离 |
| 常见误用 | 把账面领讫直接写成官物失窃 |

### E04 匠役工食册

| 项目 | 内容 |
| --- | --- |
| 类型 | 名册与支领记录，制度背景待 S08 全文核对，内容虚构 [S08] |
| 初始形成 | 灾前连续数月的匠役记录 |
| 初始持有人 | 会勘官署从废墟中收集的部分册页 |
| 完整性 | 日期连续，但包含重名、代领和去留未更新 |
| 直接支持 | 某些姓名持续出现在支领记录中 |
| 不能支持 | 所有异常都是冒领；名册中的人当天实际在厂 |
| 验证方法 | E08 街坊名册、家属证词、工友辨认、其他月份册页 |
| 争夺者 | 会勘官署、灾民互助群体、军需灰网 |
| 截止窗口 | 优恤官册封存前价值最高 |
| 常见误用 | 把同名者误作死人领饷，或以工食册直接计算死亡数 |

### E05 车辆与门禁口述

| 项目 | 内容 |
| --- | --- |
| 类型 | 多人证词，完全虚构 |
| 初始形成 | 爆炸前夜秦小乙及邻近更夫的见闻 |
| 初始持有人 | 人物记忆，无统一原件 |
| 完整性 | 时间和车辆数量说法不一 |
| 直接支持 | 当夜可能有一次不合常例的搬运 |
| 不能支持 | 车上必为火药；搬运必属违法；车辆与次日灾变有因果 |
| 验证方法 | 车辙、车行账、E03 日期、另一名更夫的报时 |
| 争夺者 | 军需灰网、内廷办事网络、玩家 |
| 截止窗口 | 第 5 日前仍可能检查车辙；此后只能依靠证词 |
| 常见误用 | 被改写成“奸细夜运炸药入厂” |

### E06 现场位置与伤痕记录

| 项目 | 内容 |
| --- | --- |
| 类型 | 观察记录，史实灾区背景、具体个案虚构 |
| 初始形成 | 胡彦清与玩家对不同区域的观察 |
| 初始持有人 | 胡彦清的私记、会勘简表、玩家笔记 |
| 完整性 | 现场持续清理，位置关系快速消失 |
| 直接支持 | 不同区域的破坏、灼伤、压伤和飞散方向并不相同 |
| 不能支持 | 仅凭宏观表象确认唯一爆心或单一成因 |
| 验证方法 | 多地点测距、不同观察者记录、搬移前标记 |
| 争夺者 | 会勘官署、抄报书坊、各种成因主张者 |
| 截止窗口 | 第 3 日后因清理和搬运大幅降值 |
| 常见误用 | 挑选最奇异的伤痕证明超常解释 |

### E07 刘六安证词

| 项目 | 内容 |
| --- | --- |
| 类型 | 幸存者证词，完全虚构 |
| 初始形成 | 爆炸当日及灾后多轮询问 |
| 初始持有人 | 刘六安本人；不同询问者各有版本 |

| C07 | “奸细纵火名单”缺乏可验证来源 | 名单来源追踪 + E05 限定 | 不能据此排除所有人为因素 |

不存在 `C09 = 已查明天启爆炸唯一真相`。

## 6. 证据污染规则

### 6.1 抄写污染

- 漏掉“不知”“疑似”“约”等限定词；
- 把数量尾数补成完整数字；
- 将两个不同见闻合并为同一证人；
- 为增强可读性补上原文没有的因果连接。

### 6.2 询问污染

- 询问者把自己的解释放进问题；
- 证人根据保护条件调整说法；
- 多次听到公开传闻后，证人把传闻纳入记忆；
- 害怕承担失慎责任的人会弱化自己在场程度。

### 6.3 政治污染

- 奏疏只摘录支持政策主张的部分；
- 会勘文本删除无法行政处理的开放问题；
- 抄报放大奇异细节与数字；
- 灰色网络不必销毁证据，只需制造一个更完整、更方便的替代版本。

## 7. 玩家写作界面需要表达的内容

最终“编成邸抄”不是选择一个结论按钮，而是为每条陈述选择：

- 事实；
- 高可信推断；
- 单一证词；
- 传闻；
- 已被推翻；
- 不公开但保留入私档。

系统结算玩家有没有把限定词删掉，而不只结算收集率。一个只找到六成证据但严格标注边界的文本，可信度应高于集齐大量材料却把推断写成事实的文本。

## 8. 转入数据前的校验

- 每项证据至少有两种取得或验证路径；
- 原件丢失后至少存在一种不完全替代路径；
- 每项公开行为同时改变传播范围与暴露风险；
- 每个结论明确列出不能推出的内容；
- 证词改口不会覆盖历史版本；
- 官档、奏疏和抄报采用不改变底层事实值；
- 史实来源只为时代背景提供约束，不把虚构证据伪装成真实发现。
