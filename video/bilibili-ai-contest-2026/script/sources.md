# 宣传片表述依据

> 用途：记录解说中的历史、创作、技术与发布状态依据。
> 原则：宣传片可以简化表达，但不能把争议材料、创作灵感或未来计划说成已经确定的事实。

## 《天变邸抄》与王恭厂灾变

- 项目内研究入口：`docs/worlds/tianqi/research/SOURCES.md`
- 当前可用于旁白的历史锚点：灾变发生于天启六年五月初六巳时，公历对应 1626 年 5 月 30 日，中心区域在京师西南王恭厂一带。
- 《天变邸抄》可作为较早、较完整且影响很大的灾变叙事版本，但不是不受质疑的“上帝视角记录”。
- 伤亡数字、奇异细节和灾变成因均不能在旁白中写成已经确认的唯一结论。
- 禁止使用“堪比核爆”“史书刻意隐瞒真相”“现代科学已经查明唯一原因”等猎奇表达。

## 《凡途》的创作来源

- 产品入口：`docs/product/PRODUCT.md`
- 可用表述：项目受到凡人流修仙叙事影响，关注信息差、准备、取舍、机缘争夺和世界不会等待玩家。
- 不使用某部小说的具体角色、门派、情节或专有设定来介绍《凡途》。
- 如果需要直接提到《凡人修仙传》，应表述为创作者接触凡人流类型的重要作品之一，而不是宣称《凡途》改编或复刻其情节。

## AI 与技术架构

- Godot：客户端界面、交互与演出。
- Go：世界规则、服务、存档、内容校验与确定性结算。
- YAML：人物、地点、事实、对话策略和表现映射等内容包数据。
- 模型：在运行时生成受到可见事实和人物策略约束的 NPC 表达，不拥有改写权威事实或直接结算行动的权限。
- AI 制作表述只使用实际发生的工作：资料整理、方案讨论、代码和配置协作、测试与媒体制作。不得使用“一句话生成完整游戏”等说法。

## 开源与发布状态

- 仓库：`https://github.com/gqy20/narra`
- 协议：MIT。
- Windows x86_64 与 macOS Universal unsigned 构建已由 GitHub Actions 验证通过。
- `v0.1.0` 已于 2026-08-05 正式发布：`https://github.com/gqy20/narra/releases/tag/v0.1.0`。
- Release 提供 Windows x86_64、macOS Universal unsigned 构建和 SHA-256 校验文件；当前发行包默认搭载《天变邸抄》。
- 正式录音 n23 前仍需重新检查 Release；只有下载页面和对应产物保持可用时，才能说“现在可以从 GitHub Release 下载”。

## 维护规则

- 修改 `narration.yml` 中的历史、技术或发布断言时，同步更新本文件。
- 解说音频逐句生成，文件名使用对应 segment ID，例如 `n01.wav`。
- 字幕文本由 `narration.yml` 生成，不维护第二份独立文案。
- 素材路径、入点和出点属于剪辑配置，不写进解说稿。
